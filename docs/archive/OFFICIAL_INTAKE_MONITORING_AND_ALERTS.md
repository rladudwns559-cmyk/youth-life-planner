# 공식 모집 자동 확인과 개인별 관심 알림

검증일: 2026-10-30 / 판단: **OFFICIAL_INTAKE_MONITORING_AND_PERSONAL_ALERTS_LOCAL_COMPLETE**

완료 범위는 단일 프로세스의 로컬 자동 확인·개인별 사이트 알림함·브라우저 Web Push 구현이다. 브라우저 기기 표시는 사용자 직접 확인으로 기록하고 자동화 도구의 독립적인 OS 표시 검증과 구분한다. 상시 배포나 전국 모든 공고의 완전 수집은 완료하지 않았다.

## 사용자 승인과 제품 범위

사용자는 공식 모집 자동 갱신과 관심 지역·사업 알림을 요청했고, 사람마다 받을 방법을 선택하도록 요청했다. 후속 답변으로 이메일은 이번 작업에서 제외했다. 전국 청년을 대상으로 하되 등록한 공식 출처의 탐색을 먼저 제공한다. 안산 전체 정책 검증/기존 PDF와 과거 milestone 이력은 유지한다.

## 실제 구현

- 기존 공식12출처와 공식 공고 목록7개, 총19개 등록 주소를 확인한다. 목록에서 관련 상세 공고를 최대16개, 목록당2개까지 추가 확인한다. 실제 최종 실행은 등록19개+상세6개=25개다.
- 서버 시작 시 작업을 등록하고 6시간마다 확인한다. 다음 확인 시각은 SQLite에 유지한다. 재시작만으로 과거 공고를 새로 발송하지 않는다. 한 번의 출처 확인은 120초, 요청10초/2MB, 푸시 전달 묶음20초/최대20건/건별5초로 제한한다. 실패 건은 최대3회까지 후속 정기 실행에서 시도한다.
- 공식 본문과 링크·이미지 주소가 기존 기준과 같은 출처는 확인일을 갱신한다. 중요한 본문이 달라지면 기존 자격/금융조건을 자동 덮어쓰지 않고 검토 대상으로 둔다. 메뉴·카운터 같은 비핵심 변경은 가능한 한 지정 본문에서 제외한다.
- 명시된 신청/접수/모집기간에 연도·날짜가 일관되게 있는 공고만 자동 일정으로 게시한다. 날짜만 있는 경우 당일 마감시각 미확인을 표시한다. 서로 충돌하는 일정·예정/추후·계좌개설/심사/교육 일정·신규 PDF/이미지 전용 일정은 확정 모집 알림으로 바꾸지 않는다.
- 새 공고/확인된 신청 시작일은 관심 지역 또는 관심 사업에 매칭한다. 지역 미확인 신규 사업을 전국 대상이라고 추측하지 않는다. 신규 사업은 공고 정보만 제공하며 자격·금융 계산은 UNKNOWN이다.
- 모집 일정이 철회되거나 다른 일정으로 바뀌어 기존 일정이 확인되지 않으면 기존 공고를 재확인 상태로 내리고, 관련 재확인 안내를 구분한다. 이미 마감된 과거 공고가 후속 반복 확인에서 새 알림이 되는 경계도 시험했다.
- 사이트 알림함/브라우저 푸시를 사용자가 각각 선택한다. 브라우저 권한은 저장 버튼을 누를 때만 요청한다. 권한 거부/미지원/연결 지연을 한국어로 안내하며 자동으로 허용 처리하지 않는다. 권한 대기는30초, 푸시 구독 연결10초, 일반 알림 API12초 제한이다.
- 실제 Web Push는 pywebpush의 표준 암호화와 VAPID 서명을 사용한다. 알림 클릭은 공식 URL 또는 로컬 알림함으로 연결한다. 민감한 계산 결과는 푸시에 포함하지 않는다. 별도 오프라인 캐싱은 하지 않는다.

## 실제 확인 결과

최종 공식 출처 실행: 25/25 응답·형식 확인 성공, not_checked0. 자동 날짜 추출3건(부산·인천·전북)은 모두 마감된 회차였다. 따라서 현재 실제 신규 모집 알림은0건이며, 실제 공고나 참가자 응답을 만들지 않았다. 기존10사업은 상시 가입 안내1·마감8·미운영1을 유지한다. 이3건 추출 성공을25건 모두 일정 검증으로 해석하지 않는다.

실제 알림 API17사례에서 생성한 비공개 검증용 구독으로 알림함의 TEST1건·읽음·삭제·인증/Origin/개인정보 거부를 확인했다. 검증용 구독은 삭제했다. 기존 공식사업11사례와 정책/What-if/적금/상품/정형설명5개 실제 HTTP 스크립트도 통과했다.

사용자 답변: “브라우저 테스트 알림이 떴어”. 이를 **USER_REPORT / 기기 표시 사용자 확인**으로 기록한다. 브라우저 자동화는 현재 URL을 안전하게 판별할 수 없다는 도구 제한으로 중단되어 자동화된 OS 표시 확인은 수행하지 못했다. 이후 서버에 남은 TEST 전송 집계는 비어 있어 해당 표시의 대응 전송 로그를 독립적으로 확인하지 못했다. 삭제 이력이나 원인을 추정하지 않는다. 사용자 확인과 서버 전송 접수/독립 표시 검증을 구분한다.

## API와 구조

- `backend/asset_alerts/sources.py`: 신뢰 URL·선택자·날짜 파서·일정 상태.
- `runtime.py`: SQLite, 구독·알림함·중복 방지·만료·작업 lease·주기 작업.
- `delivery.py`: 브라우저 endpoint 검증, 암호화/VAPID, 리다이렉트 금지·유한 시간 전송.
- `catalog_view.py`: 동일 본문의 확인일만 갱신, 변경 본문의 기존 모집 정보 재검토 표시.
- `backend/web/asset_alerts.py`: 공개 상태/명시 구독/설정·조회/읽음/삭제/구분된 테스트 알림.
- `frontend/src/AssetAlerts.tsx`: 지역·사업·채널 설정과 알림함·자동 확인 일정.
- `frontend/public/asset-alerts-sw.js`: 실제 push 수신·showNotification·공식 페이지 클릭.

`GET /api/asset-alerts/status`, `POST /subscriptions`, `GET/DELETE /subscription`, `GET /inbox`, `POST /inbox/{id}/read`, `POST /test`. 상태 이외 경로는 비공개 Bearer 식별자를 요구한다(신규 구독 생성 제외). 변경 요청은 지정 Origin과 전용 헤더를 검증한다. 토큰/endpoint/개인 입력을 URL이나 증거 출력에 넣지 않는다. /test는1분당1회, 다른 사람의 대기 메시지를 대신 전달하지 않는다.

## 데이터와 개인정보

구독은 관심 지역·사업, 전국/모든지역 선택, 알림함/브라우저 수신 방법, 필요한 push endpoint/key, 생성·만료 시각만 저장한다. 소득·지출·생년월일·계좌정보는 이 저장소에 받지 않는다. 브라우저에는 무작위 비공개 구독 식별자만 저장하고 서버는 그 해시를 저장한다. 브라우저 구독 endpoint는 공개하지 않는다.

구독은90일 후 만료된다. 만료된 설정과 오래된 알림은 서버의 정기 확인 때 지운다. 서버가 꺼진 동안 물리 파일 삭제가 실행된다고 약속하지 않는다. 구독 삭제는 서버의 관심 설정·endpoint·개인 알림 기록과 브라우저 식별자/푸시 구독을 지운다. OS 사이트 알림 권한 자체는 사용자의 브라우저 설정에서 관리한다.

런타임은 무시되는 `tmp/asset-alerts-runtime/state.sqlite3`, VAPID 개인키는 같은 디렉터리의 `vapid-private.pem`이다. source/evidence/Vault에 복사하지 않는다. SQLite secure_delete를 사용한다. 로컬 사용자 영역에 보관하며 공개 운영을 위한 계정/기기 복구·다중기기 접근·저장소 암호화/권한 운영은 별도 검토가 필요하다. 이번은 단일 로컬 프로세스만 검증했다.

## 최초 실패·보완·재실행

1. 신규 의존성은 공식 PyPI의 beautifulsoup4 4.15.0 / pywebpush 2.5.0으로 고정했다. dry-run에서 기존 설치 패키지 업그레이드 없이 신규 의존성만 추가하는 것을 확인했다. 환경 전체를 재설치하지 않았다.
2. 첫 실제 수집은18/27 성공. PDF가 x-download로 응답하는 문제, 경남 목록의302/HTTP 안내 경로, 일부 과거 서울 상세 응답 오류를 구분했다. PDF magic 검증·확인된 HTTPS 경남 주소·연도/목록별 예산을 반영한 뒤25/25 성공했다. 실패 원본 로그를 보존한다.
3. 관련 Backend 첫 실행2실패: 날짜 충돌 fixture가 두 HTML 문서를 붙인 잘못된 구조여서 정상 단일 본문 fixture로 수정했다. VAPID 라이브러리의 subject 검증은 개발 주소의 끝 슬래시를 거부해 올바른 URI와 예외 처리를 반영했다.
4. 과거 마감 일정이 변경 후 반복 조회에서 재확인 알림으로 올라가는 경계 결함을 고쳤다. 기존 종료 상태와 invalidation hash를 보존하고 중복을 막았다.
5. 신규 UI 테스트2개는 날짜와 합쳐진 문구의 정확 일치 query를 범위 검사로 고쳤다. 기존 ‘알림 미구현’ 임시 안내 테스트1개는 이번 승인된 채널 안내로 갱신했다. 새 모듈은 기존6개 화면 테스트에서 격리하며 계산 기대값은 유지했다.
6. TS의 작업 디렉터리 착오와 신규 테스트의 미사용 import2개를 수정했다. 최종 타입 검사·전체 Frontend161·빌드를 다시 통과했다.
7. 전체 Backend 최초1실패는 별개 브라우저 fixture가 동일 endpoint를 써서 실제 소유권 보호에 막힌 경우였다. 서로 다른 합성 endpoint로 바로잡고 전체를 다시 통과했다.
8. 기존 HTTP 복사본의 ‘알림 false’ 임시 경계만 true로 갱신했다. 원본 증거는 보존했다. 페이지 전체 fingerprint가 비핵심 메뉴 변경을 잡는 사례는 두 상품정보 탭의 본문·링크·이미지가 기존 공식 캡처와 실제로 같음을 확인한 뒤 두 탭 전체를 비교하도록 보완했다. 필수 탭 누락/두 번째 탭 변경 거부 테스트2개를 추가하고 최종 전체12562를 재실행했다.
9. 실제 화면에서 기존 전역 legend float가 새 설정 폼을 밀어내는 것을 확인하고 새 폼 범위에서 float/width를 재정의했다. IAB 권한 대기가 끝나지 않는 경우를 위해30초 제한을 추가했다. 이후 URL 안전 판별 실패로 UI 자동 조작을 중단했고 사용자에게 실제 테스트를 요청했다. 최종 기기 표시는 사용자 답변으로만 기록한다.

## 기존 계약 보존

기존396개 SHA256 기준선에서 코드/설정 변경은 router/lifespan 연결, 공식사업 응답의 갱신 표시, UI·알림 안내, 의존성, 신규 모듈 테스트 격리뿐이다. 실제 release6개 모두 SHA256 불변. Policy/Cashflow/M3.2/Coverage/Acceptance/Historical 소스와 GV/BV golden fixture는 그대로다. 실제 금융상품 만기 계산0개·미승인 정책 지원금 반영0원. 실제 정책 DRAFT/CONDITION_SLICE·ResidenceHistory OFFICIAL_INQUIRY_REQUIRED·M2.77 SYNTHETIC_ONLY 유지.
