# 프론트엔드 금융 서비스 스타일 개편

기록일: 2026-10-29. 범위: M3 시제품의 화면 구성과 스타일 개선. 실제 정책·상품 검증이나 사용자 이해도 평가의 완료를 뜻하지 않는다.

## 변경 내용

| Before | After | Why |
|---|---|---|
| 초록 계열의 입력 중심 화면 | 네이비·블루, 서비스 소개와 실제 동작하는 메뉴/시작 링크 | 금융 서비스의 정보 위계와 시작 동선을 명확히 한다. |
| 입력/결과/비교의 작은 글자와 제각각 여백 | 폼·금액·정책 상태·적금·상품·설명의 공통 스타일 | 계산 결과와 추가 확인사항을 쉽게 구분한다. |
| 간단한 비어 있는 결과 영역 | 직접 작성한 SVG/CSS 그래픽과 결과 안내 | 입력 후 무엇을 확인할 수 있는지 설명한다. |
| 흩어진 사용 가정 | 이용 안내 아코디언과 시제품 고지 | UNKNOWN·저축 상한·합성 계산·개인정보 처리의 의미를 제공한다. |

수정: frontend/src/App.tsx, frontend/src/styles.css, frontend/index.html. 추가: frontend/src/ServiceShell.tsx. ServiceShell은 표시 전용이며 계산/판정/요청 로직이 없다. App 상태·이벤트·요청 정의는 기존과 동일함을 작업 도구로 대조했다. 기존 기능의 버튼명·입력명·테스트 ID·API 계약을 유지했다. 의존성 설치/폰트 CDN/분석 추적/모델 실행은 추가하지 않았다.

## 디자인 참고와 스킬

[카카오뱅크 공식 홈페이지](https://www.kakaobank.com/)와 [토스뱅크 공식 홈페이지](https://www.tossbank.com/)의 공개 메뉴·서비스 소개 구성을 참고했다. 특정 은행의 로고·이미지·문구를 복제하지 않았으며 일러스트는 직접 작성한 SVG/CSS다. emil-design-eng와 mobile-native 지침에서 정보 위계·정확한 전환 속성·키보드 포커스·터치 입력·16px 입력·감소된 모션 대응을 적용했다. 이미지 생성/새 플러그인 설치는 하지 않았다.

## 오류와 해결 이력

1. 320px 첫 시험에서 body 최소 폭 및 상단 메뉴 때문에 가로 넘침(305/320)이 발생했다. CSS 최소 폭/좁은 헤더 여백·글자 크기를 수정해 305/305로 재확인했다.
2. HTTP 일괄 명령의 마지막 파일명을 explanations-live-http.mts로 잘못 지정해 앞 4경로 통과 후 MISSING으로 종료했다. 실제 파일명 explanation-live-http.mts를 확인해 별도 실행했고 통과했다. 테스트 소스 변경은 없다.
3. 추가 API 서버 실행 시 이미 열린 8100 포트 때문에 새 프로세스가 종료됐다. 기존 서버의 실제 API/HTTP 응답을 확인해 사용했다. 기존 사용자 프로세스를 임의 종료하지 않았다.
