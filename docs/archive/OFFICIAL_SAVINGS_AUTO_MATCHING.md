# 공식 적금 금액·기간 자동 매칭

검증일: 2026-10-30 KST. 사용자 요청: IBK 과거 3개 외 다른 은행의 최신 공식 자료를 추가하고, 입력한 저축 가능 금액·기간에 맞는 적금을 자동 표시한다.

## 실제 결과와 사용법

카카오뱅크 1개, 케이뱅크 2개, 토스뱅크 1개를 새로 추가했다. 신규 자동 매칭 대상은 **3개 은행/4개 상품**이다. 기존 IBK 3개/2025-12-31 기준 자료는 별도의 ‘이전 IBK 상품 자료 비교 · 2025년 기준’ 영역에 보존한다. 전체 정보는 4개 은행/7개 상품이지만 최신 자동 매칭 대상과 과거 자료를 합쳐 7개를 최신이라고 표시하지 않는다.

현재 상황의 월 수입·지출·사용자 저축 상한과 새 ‘목표 저축 기간’을 입력하고 ‘내 상황으로 계산하기’를 누른다. 기존 Python Cashflow의 `savable_amount`와 입력 기간으로 자동 조회한다. 이후 목표 기간 변경 시 자동 재조회하며, What-if 비교 완료 후 ‘변경 후 예산 기준’으로 목록 변화를 볼 수 있다. 목표 기간은 기본 계산과 독립적이며 빈칸/유효하지 않은 값이면 상품만 보류한다.

## 매칭 계약과 Assumption

1. **월 저축 투입 상한 전체**를 납입할 계획으로 비교한다. 50만원을 30만원으로 자동 축소하거나 여러 상품으로 나누지 않는다. 한도 초과/최소 미달/선택 기간 불일치를 이유와 함께 표시한다.
2. 코드K의 이산 기간(1·3·6·12·24·36)을 연속 범위로 확장하지 않는다. 확인된 납입 단위만 검사한다. 미확인 단위는 상세의 추가 확인으로 남긴다.
3. 핵심 한도·기간 누락, 판매 확인 불충분, 확인일이 미래이거나 검토 기한 경과 시 자동 매칭에서 제외하고 재확인 영역에 표시한다. 금리가 없으면 ‘미확인’이며 0%로 바꾸지 않는다.
4. **Assumption: 확인 후 7일**을 서비스 재검토 간격으로 정했다. 7일 경과까지 허용하고 8일째 보류한다. 현재 자료는 2026-11-07부터 재확인 대상이다. 은행 금리 유효기간이나 지속 가입 가능성을 보장하는 기준이 아니다. 자동 수집/예약 작업은 추가하지 않았다.
5. 금액·기간 일치와 실제 가입 자격을 구분한다. 계좌 보유·가입 제한·나이·개별 은행 승인·우대조건 충족은 `NOT_EVALUATED`/`UNCONFIRMED`로 유지한다. 순위/최적 수익 추천을 만들지 않는다.
6. 모든 실제 상품은 `NOT_VERIFIED`, 계산 값은 null, 실제 만기 계산 수는 0이다. 기존 M3.2 합성 계산기는 바꾸거나 실제 상품에 연결하지 않았다.

## 오류·수정 이력

1. 토스 공시실 다운로드의 숨은 아코디언과 기다림 오류가 있어 처음에는 다른 상품(굴비) PDF가 내려왔다. 화면의 자유적금 항목을 다시 확인해 올바른 실제 자유적금 PDF를 확보했다. 굴비는 대상에 넣지 않았다.
2. 최초 TypeScript 검사에서 새 테스트의 미사용 import와 빈 배열의 never[] 추론 두 문제를 발견해 새 테스트 타입만 보완했다. 기존 테스트/기대값 변경0. 마지막 전체 테스트·타입·빌드 통과.
3. What-if 브라우저 자동화의 ‘선택’ 라벨 정확 일치가 실패해 현재 AX 입력을 확인하고 해당 입력을 조작했다. 제품의 사용자 입력 오류가 아니며 정상 비교를 완료했다.
4. 코드K에 별도 우대가 반영된 것처럼 보일 수 있는 공통 문구를 ‘별도 우대금리 미반영’으로 구분하고 최종 회귀했다. 첫 PowerShell 문구 수정 명령은 따옴표 구문 오류로 실행되지 않았으며 올바른 파일 복사로 적용했다.

## 보존 감사와 다음 작업
