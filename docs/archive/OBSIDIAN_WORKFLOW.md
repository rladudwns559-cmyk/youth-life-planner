## 마일스톤 완료 순서

1. 승인된 코드 구현과 실제 테스트를 먼저 완료한다. 미실행 시험은 미실행으로 남긴다.
2. 최종 판단/한계와 신규·전체 테스트/skip/warning을 원본 저장소 보고서에 기록한다.
3. Vault `03_개발 기록`에 `90_템플릿/마일스톤 완료 템플릿.md` 양식으로 노트를 추가한다.
4. Properties: type=milestone, project=AI+X, milestone, status, 실제 date, evidence, verification, verdict, tags를 기록한다.
5. evidence는 직접 검증/저장소 보고/미실행/합성 시험만 완료/운영 검증 보류 등을 실제 증거에 맞게 구분한다. 완료와 운영 승인을 분리한다.
6. `00_홈/현재 개발 상태.md`, `06_테스트와 품질/테스트 대시보드.md`, `회귀 테스트 기록.md`를 필요한 범위만 갱신한다.
7. `이번 주 할 일.md`의 실제 완료만 체크한다. 제안을 승인된 다음 작업으로 바꾸지 않는다.
8. 대시보드의 최신 링크/숫자를 갱신하고 Bookmarks의 최신 마일스톤 대상도 확인한다. 실행 중인 앱의 설정 파일은 무단 덮어쓰지 않는다.
9. Bases는 type/project/폴더 조건으로 새 마일스톤을 자동 표시한다. 템플릿 폴더는 제외한다.
10. Wikilink 파일/제목/블록, source_paths의 실제 경로, Canvas/Bases의 참조를 확인한다. GUI에서 본 것과 파일 검사만 한 것을 구분해 보고한다.

## 충돌·연결 실패

Vault가 없거나 쓰기 권한이 없으면 원본 개발을 막지 않는다. 저장소 보고에 문서 동기화 미완료/대상 경로/미갱신 항목을 명시한다. 다른 보관함이나 원본 저장소로 자동 대체하지 않는다.
사용자가 수정한 절과 충돌하면 해당 사실을 보존하고 필요한 부분만 합친다. 모델/설계만 존재하는 기능을 구현 완료로 쓰지 않는다.
