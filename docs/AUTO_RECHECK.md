# 금융 상품 자동 대조 (2026-11-11)

추천에 나올 수 있는 예·적금 상품의 기한(확인일 + 7일)을 사람이 매주 다시 읽지 않아도 이어 가기 위한 장치. API 키가 필요 없고 무료(GitHub Actions)다.

## 하는 일
`tools/auto_recheck.py`가 매일 06:30(한국시간)에 GitHub Actions(`.github/workflows/auto-recheck.yml`)에서 실행된다.

1. 추천 후보 상품마다 이미 기록된 공식 출처(상품 페이지, 목록, PDF)를 실제 브라우저(Chromium)로 열어 화면 글자를 읽는다. PDF는 본문을 추출한다. 케이뱅크는 상품 페이지가 스스로 불러오는 금리 자료를 읽는다.
2. 아래 **세 가지가 모두 맞을 때만** 그 상품의 확인일을 오늘로 바꾼다(기한 7일 연장).
   - 상품명이 페이지에 있다.
   - 상품명 바로 뒤에 판매중단·판매종료 표시가 없다.
   - 저장된 기본금리들이 **기간 순서대로, 가까이 모여서**(2,500자 안) 페이지에 있다. 금리가 하나뿐이면 "기본·금리·이율" 글자 가까이에 있어야 한다.
3. 하나라도 안 맞거나 페이지를 못 읽으면 **아무것도 바꾸지 않는다.** 그 상품은 기존 기한이 지나면 추천에서 자동으로 빠진다.
4. 바뀐 것이 있으면 시험 3개를 통과한 뒤 커밋하고 공개 사이트를 다시 배포한다.

금리를 새 값으로 고치는 일은 하지 않는다. 금리가 바뀐 상품은 사람이 읽고 넣어야 한다.

## 사람이 읽은 것과 구분
자동 대조는 사람이 읽는 것보다 약한 확인이다. 그래서 자동으로 갱신한 기록은
- 근거 문장이 `automated comparison ... (not a human reading)`으로 시작하고,
- 출처 제목 끝에 `(자동 대조)`가 붙고,
- 그날 읽은 출처 하나만 남긴다.

입력 파일은 `data/financial-products/renewals/<날짜>/auto-reviewed.json`이다.

## 알려진 한계
- 최고금리 열에 예전 기본금리와 같은 숫자가 순서에 맞게 있으면, 바뀐 금리를 "같다"고 잘못 볼 수 있다. 순서와 거리 조건으로 줄였지만 0은 아니다.
- 금리가 하나뿐인 상품은 대조가 약하다.
- 은행이 화면 구조를 바꾸거나 해외 접속을 막으면 `UNREADABLE`/`MISMATCH`가 되어 갱신되지 않는다(안전한 쪽으로 실패).
- **새로 나온 상품을 찾아 넣지는 못한다.** 이미 목록에 있는 상품의 기한만 이어 간다. 새 상품 추가는 사람이 공식 페이지를 확인해 넣어야 한다. 금감원 Open API는 약관이 자료 저장을 금지해 쓰지 않았다([FINLIFE_AUTO_REFRESH.md](FINLIFE_AUTO_REFRESH.md)).
- 청년 지원사업(정책)은 대상이 아니다. 문장형 조건이라 같은 방식으로 대조할 수 없다.

## 직접 돌려 보기
Actions 탭 → "Auto recheck financial products" → Run workflow. `dry_run`을 켜면(기본) 자료를 바꾸지 않고 상품별 결과만 보여 준다. 결과 목록은 실행 화면의 `auto-recheck-report` 파일로도 받을 수 있다.

결과 값: `RENEWED`(갱신), `MISMATCH`(이름·금리가 안 맞음), `UNREADABLE`(페이지를 못 읽음), `SKIP`(오늘 이미 확인함).

## 끄는 법
Actions 탭에서 이 워크플로를 Disable 하거나 `.github/workflows/auto-recheck.yml`을 지운다.
