## 판정 및 개인정보

- 새 discovery 계층은 기존 evaluate_policy와 생년월일 evaluator를 재사용한다. 기존 엔진을 수정하거나 전체 eligibility coverage를 통과 처리하지 않는다.
- 현재 지역/기본 연령/입력한 생년월일·주택 소유 여부/일부 취업 정보만 기초 조건으로 비교한다. 공고 기준 주민등록, 건강보험료, 소득인정액, 가구원·재산·중복참여·선발·유지조건은 추가 확인한다.
- 월 생활비 소득을 공식 연소득·소득인정액으로 환산하지 않는다. 현재 만 나이를 과거 신청 시점 나이로 사용하지 않는다. 병역 특례가 미확인인 상한 초과는 UNKNOWN으로 남긴다.
- 사업 모두 DRAFT / CONDITION_SLICE이며 남은 조건을 필수 UNKNOWN으로 제공한다. 기본조건 일치가 전체 자격 PASS/신청 가능 확정을 뜻하지 않는다. 전체 결과는 FAIL 또는 UNKNOWN이다.
- 기존 Cashflow의 savable_amount를 사용한다. 예산 부족·납입한도·초과 여유자금·목표 기간 차이를 자격 요건과 분리한다. 최소 납입액 미확인은 임의로 만들지 않는다.
- 추가정보는 선택 입력이다. 서버는 요청 단위 계산만 하고 영구 저장하지 않는다. 브라우저 입력도 localStorage에 저장하지 않는다. 원문 입력의 오류 응답 노출을 막고 기존 no-store 계약을 따른다.
- 모집 현황은 확인된 공식 스냅샷과 현재 KST로 계산한다. 7일 확인 주기는 운영상 Assumption이며 법령 기준이 아니다. 8일째부터 모집 중/예정 표시는 재확인 필요로 내려간다. 자동 실시간 수집/상시 감시는 미구현이다.

## 실제 연결

- backend/opportunities/catalog.py: 엄격한 카탈로그/출처/날짜 검증.
- matching.py: 모집과 기초 조건·예산·미확인 조건 분리 및 Before/After.
- changes.py: 검증된 두 스냅샷 간 안정적인 공개 변경 이벤트. NOT_SENT.
- GET /api/asset-programs: 비로그인 공개 목록.
- POST /api/asset-programs/recommendations: 기존 profile, 선택 supplement·after_profile·goal_months. 저축 가능액은 기존 엔진으로 산출한다.
- frontend/src/AssetPrograms.tsx: 공개 검색/모집 필터, 입력 후 자동 추천, 추가정보, 전후 전환, 공식 링크·확인일·UNKNOWN 표시. 10초 요청 제한·오류 안내·수동 재시도. 자동 재시도 없음.
- tools/check_asset_program_sources.py: 등록 공식 URL만 크기2MB/시간10초/리다이렉트 금지로 확인한다. 바이트 변화는 수동 검토 후보이고 자동 규칙 생성·verified_on 갱신·알림 발송을 하지 않는다.
