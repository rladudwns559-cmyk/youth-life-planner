# 제품 품질 점검과 추천 흐름 통일

확인일: 2026-11-06. 기존 공개 v23을 기준으로 한 제품 개선 기록이다. 과제 문서의 가상 기획 시점과 실제 구현 상태는 구분한다.

## 참고 서비스와 적용 범위

- [온통청년 청년정책 통합검색](https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch): 상세 검색과 공식 정책 안내를 확인했다. 우리 목록의 검색·필터 동선을 점검하는 기준으로 참고했다.
- [복지로 공식 서비스 소개](https://www.bokjiro.go.kr/ssis-tbu/cms/pc/intro/intro/info/01/index.html): 서비스찾기·모의계산·맞춤형급여안내의 역할 구분을 참고했다. 다른 서비스의 수급 판정이나 개인정보 연동을 가져온 것은 아니다.
- 금융감독원 금융상품한눈에 직접 접속은 이번 조사에서 시간초과로 확인하지 못했다. 화면을 직접 검토했다고 주장하지 않는다.

다른 서비스의 디자인 자산·소스코드·개인정보를 복제하지 않았다. 기존 브랜드와 React/FastAPI 구조를 유지했다.

## 발견한 문제와 변경

| Before | After | Why |
| --- | --- | --- |
| 이용 안내에 금융상품 113개가 남음 | 실제 공개 집계의 46개 회사·326개 상품/가입유형과 연결 | 화면마다 수치가 달라지는 문제 방지 |
| 결과 창 안의 상품은 금액 조건만으로 나열 | 별도 상품 페이지와 같은 Python 준비표의 기본금리 순서·상위 추천 표시 | 동일 입력에서 같은 추천 근거 제공 |
| 지원사업 목록에서 모집 필터를 바꾸려면 조건 화면으로 이동 | 목록 안 모집 필터와 공고 마감일 정렬 | 검색·관심사업을 유지하며 탐색 |
| 확인일과 현재 날짜의 의미가 눈에 잘 들어오지 않음 | 확인일·화면 기준일·금융 재확인 기한을 별도 안내 | 화면을 열었다고 최신 검증으로 오인하지 않도록 함 |
| 결과 창에서는 관심 저장 불가 | 기존 관심사업 저장소와 연결 | 검색 → 저장 → 목록 확인 흐름 완성 |
| 결과 창에서 저장 실패 안내가 보이지 않음 | 활성 결과 창 안에 저장 실패·메모리 유지 안내 | 실제 영구 저장 여부를 구분 |
| 렌더/동적 화면 오류 시 빈 화면 가능 | 새로고침과 공식 검색 경로를 제시하는 오류 복구 화면 | 실패 뒤 사용자가 할 행동 제공 |

마감일 정렬은 자격 판단이 아닌 표시 순서다. 다른 지역·명시적 조건 불일치는 계속 구분하며, 상시·지난 날짜·일정 미확인·유효하지 않은 날짜를 긴급 마감 사업으로 꾸미지 않는다. 마감일 정렬 설명과 추천순 설명도 구분한다. 조건 입력에서 결과를 다시 열면 추천순으로 돌아간다.

## 실제 검증

- 최종 Frontend: **406 passed, 34 files passed**. 기존 391개 기대값과 테스트를 수정하지 않았고 신규 15개를 추가했다.
- 신규 검증: 자료 확인일과 화면 날짜 구분, 기존 유효기간 경계, 실제 집계 수치 표시, 고정된 추천 상위 3개와 양쪽 화면의 일치, 만료 후 추천 보류, 렌더 오류 복구, 날짜 예외, 목록 필터 상태 유지, 마감 정렬, 사업 ID만 저장, 저장 실패 안내.
- 집중 검증: 5개 파일 26 passed. 이후 관심 저장 검증 2개를 추가하고 최종 전체 회귀에 포함했다.
- TypeScript 검사 및 공개 모드 Vite build 성공. 500kB 이상 청크 경고는 남아 있다. 경고 기준을 높이거나 숨기지 않았다.
- 원본 Backend 전체 회귀: **12,820 passed / 1 skipped / 1 warning**, 99.95초. 기존 NTFS symlink 관련 미실행 한계와 Starlette/httpx 경고를 유지한다. 소스 변경은 없으며 결과를 공개 서버 운영 검증으로 취급하지 않는다.
- 보호 범위: 기존 698개 파일의 SHA256 기준선 중 backend/data/tests/tools/public-data 289개 불변. 실제 release 6개와 golden/fingerprint 관련 7개 파일도 불변. 공식 데이터·금리·기간·모집 조건을 이번 작업으로 다시 검증한 것으로 표시하지 않았다.

### 화면에서 확인한 경로

1. 빈 조건으로 찾기 → 조건 입력 안내.
2. 경기·안산시 상록구·만24세·근로 중·월세 → 다른 시군구보다 경기도·전국 검토 후보 우선. 소득·재산 등은 추가 확인.
3. 결과 창에서 관심 저장 → 목록의 관심사업에 동일 선택 유지.
4. 목록에서 공식 접수 필터·공고 마감일 순 선택 → 지역·나이 입력 유지, 안내 문구와 정렬 대응.
5. 월30만원·12개월 → 두 상품 탐색 화면의 상위 추천 ID 동일:
   - NOV3-SB-BULIM-TOK-SAVE
   - NOV3-SB-MOA-E-SAVE
   - KAKAO-FREE-SAVINGS
6. 숫자 입력은 `300,000` 표시. 실제 계산/조회 입력은 원래 정수값 유지.
7. 390px 모바일 폭에서 지원사업 필터·상품 추천 확인. 문서 폭 375px로 가로 넘침 없음. 실제 휴대전화 하드웨어 시험과 혼동하지 않는다.

### 최초 실패와 재검증

- 최초 실행은 연결된 node_modules 폴더의 쓰기 권한 오류로 테스트 시작이 막혔다. 시간 제한을 바꾸지 않고 정상 권한으로 실행했다.
- 신규 검증 코드에서 JSON의 튜플 추론 때문에 TypeScript 오류 1건을 발견해 타입 표기만 보완했다.
- 구현 중 실행한 중간 전체 시험에서 관심 저장 신규 2건이 실패했다. 최종 저장 UI 반영 후 소스를 고정하고 전체를 다시 실행해 406개를 통과했다. 중간 결과를 최종 증거로 사용하지 않는다.
- 한 번의 준비 명령은 작업 디렉터리 경로 오류로 실패해 해당 실행을 중단했다. 최종 전체 검증은 별도 로그로 구분했다.
- 기존 테스트 기대값, timeout, golden을 바꿔 통과시키지 않았다. 실제 LLM 추가 실행은 하지 않았다.

## 완료와 남은 범위

이번 작업은 추천 흐름·검색 동선·정보 표시·복구 동작의 품질 개선이다. 다음 상태를 승격하지 않는다.

- 실제 금융상품 만기금액 계산 연결 0개, 검증되지 않은 정책 지원금 Cashflow 반영 0원.
- Policy PASS/FAIL/UNKNOWN, Coverage freeze, Acceptance/Historical, LLM 후보 검사·Output Validator·Fallback·시간 제한 유지.
- 실제 안산 정책 DRAFT/CONDITION_SLICE, ResidenceHistory OFFICIAL_INQUIRY_REQUIRED, M2.77 SYNTHETIC_ONLY 유지.
- 공개 사이트는 정적 스냅샷 기반이며 상시 Python/LLM 서버, 자동 갱신·푸시·이메일 알림이 없다.
- 금융 스냅샷 재확인 기한은 **2026-11-06 그대로**다. 기한을 지난 후에는 기존 계약대로 금리 추천과 금액·기간 일치 표시를 보류한다. 자료 검토일을 임의로 오늘로 바꾸지 않았다.
- 실제 사용자 3명/5명의 이해도 향상을 이번 화면 시험으로 입증하지 않는다.
- Obsidian은 파일 갱신과 링크 검사를 별도 기록하며 앱 GUI 검증으로 주장하지 않는다.

다음 최우선 운영 작업은 만료되는 공식 금융 근거를 다시 확인하고, 확인한 상품만 새 스냅샷으로 갱신하는 것이다. 외부 은행 검산 정답이 없는 상태에서 실사용 만기 계산을 연결하지 않는다.
